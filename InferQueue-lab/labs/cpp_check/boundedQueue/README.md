### 整体执行流程
创建线程池，启动固定数量的工作线程
        ↓
工作线程在空队列上等待
        ↓
主线程 submit 提交任务，保存对应的 future
        ↓
工作线程从队列取出任务，释放队列锁后执行
        ↓
任务返回值或异常保存到共享结果状态
        ↓
主线程通过 future.get() 获取结果
        ↓
关闭队列，处理完已有任务，join 回收线程
1. 任务、队列与工作线程

using Task = std::packaged_task<int()>;

表示任务不接收参数，返回一个 int。任务需要的数据可以通过 lambda 捕获。

packaged_task 不会自动创建线程，也不会在构造时执行任务。工作线程调用 task() 时，才真正执行包装的函数。

工作线程循环：

for (;;) {
    Task task;

    if (!queue_.pop(task)) {
        break;
    }

    task();
}

pop() 返回后队列锁已经释放，因此执行耗时任务不会一直占着队列锁。

2. 为什么空队列不会立即 break

关键等待条件：

not_empty_.wait(lock, [this] {
    return closed_ || !queue_.empty();
});

谓词为 true 表示可以结束等待，为 false 表示继续等待。

结束等待：队列已关闭，或者队列非空
继续等待：队列未关闭，并且队列为空

队列状态

pop() 的行为

未关闭、为空

在内部等待，不返回

未关闭、有任务

取出任务，返回 true

已关闭、有任务

继续取出已有任务，返回 true

已关闭、为空

返回 false

外层 if (!queue_.pop(task)) 必须先等 pop() 返回，才能判断是否执行 break。

等待期间会释放锁，醒来后重新取得锁并检查条件。即使收到通知，也不能直接假定队列一定有任务。

3. 关闭与退出

close() 的约定：

拒绝新任务。

唤醒等待空位的生产者和等待任务的消费者。

已接收的任务继续执行。

队列关闭且为空后，消费者退出。

析构时：

queue_.close();

for (auto& worker : workers_) {
    worker.join();
}

先关闭，再等待线程结束。close() 本身不代表所有任务已经执行完。

4. RAII 与锁

lock_guard 和 unique_lock 是管理锁的对象。

离开作用域时，如果锁管理对象仍拥有锁，其析构函数会释放锁。提前 return 或正常异常展开也会触发这一过程。

区别：

lock_guard：适合简单的作用域加锁。

unique_lock：支持等待期间解锁、醒来后重新加锁，适合配合条件变量。

5. lambda 捕获

写法

含义

[id]

保存创建 lambda 时的编号副本

[&hits]

通过引用访问外面的统计数组

[id, &hits]

编号独立保存，统计数据共享

[this]

保存当前对象指针，用于访问成员

引用捕获不会延长变量生命周期，也不会自动提供线程安全。

任务编号 id 应按值捕获。若引用循环变量，任务执行时它可能已经改变或被销毁。

6. future 与异常

get_future() 获取任务对应的结果对象，不执行任务。

future.get()：

结果未准备好时等待。

结果准备好后取得返回值。

任务抛出异常时重新抛出该异常。

普通 future 的结果只能取一次。
9 月 24 日：验收与性能实验

1. 正确性检查

实际日志中，六项测试连续运行五次，均通过：

拒绝零工作线程、零队列容量。

1000 个编号任务返回正确结果，每个编号执行一次。

任务异常能通过 get() 传回，工作线程继续处理后续任务。

关闭后拒绝提交，重复关闭安全。

析构时处理完已接收任务并回收线程。

满队列上的等待提交者能被关闭操作唤醒。

“不丢不重”应检查每个编号的执行次数，而不只是检查总数。

5. task_count 与 get 的位置

task_count 是总任务数量，不是线程数，也不是队列容量。

64 个任务可以由 4 个工作线程反复取出、执行。

如果每次提交后立刻 get()：

for (...) {
    auto result = pool.submit(...);
    result.get();
}

主线程会等当前任务完成，再提交下一个任务，限制这批任务的并行。

批量实验应先提交多个任务、保存 future，再集中获取结果。按顺序 get() 不会阻止其他已提交任务并行执行。
